# F1 — تحقیق میدانی و اعتبارسنجی درد

- **بازه:** هفتهٔ ۲ تا ۶ (موازی با پایان F0 و آغاز F2) · **گیت خروج:** G1
- **هدف:** پیش از ساخت، ثابت کنیم (الف) درد فراوان و واقعی است (ب) برش انتخاب‌شده درست است (ج) کاربر برای «پاسخ درست» وقت/پول می‌دهد (د) دقیقاً چه چیزی را نمی‌فهمد.
- **Trace:** T02 (پرسونا و نقشهٔ درد) · T12 (MVP) · T06 (اصول رابط که در مصاحبه آزموده می‌شود) · T10 (نقطه کور ۱۰: کاربر خسته)

> ⚠️ T12 صریح است: «تحقیق میدانیِ بخش T02 **پیش از** ساخت MVP اجرا شود.» این فاز تنها جایی است که اشتباه‌کردن ارزان است؛ آن را سبک نگذران.

## ۳. گیت خروج G1

- [ ] ≥ ۳۰ مصاحبهٔ معتبر (با متن/ضبط) + ≥ ۱۰ مصاحبهٔ عمیقِ پرونده‌دار.
- [ ] ≥ ۲۰ فیش + ≥ ۱۰ حکم واقعیِ بی‌نام با فرم رضایت **موجود و قابل استناد**.
- [ ] ≥ ۶۰٪ مصاحبه‌شوندگان گفته‌اند «اگر پاسخ دقیق و مستند بدهد، هر هفته استفاده می‌کنم» (آستانهٔ پیشنهادی — بازسنجی‌شدنی).
- [ ] حداقل ۳۰٪ گفته‌اند حاضرند برای خدمت دقیق مبلغی بپردازند (وگرنه D4 به B2B2C خالص تغییر می‌کند).
- [ ] نقشهٔ درد ۵تایی با امتیاز و بدون «دردی که با قانون مکتوب قابل پاسخ نیست».
- [ ] پروتوتایپ با ۱۲ کاربر آزموده و «زمان تا اولین پاسخ مفید» ≤ ۳۰ ثانیه ثبت شده باشد.
- [ ] آزمون رقبا نشان دهد دست‌کم ۵/۱۰ سؤال برش MVP را رقیب عمومی غلط یا کلی پاسخ می‌دهد (اثبات تمایز؛ اگر نه → بازنگری استراتژیک).

## ۴. خارج از دامنهٔ F1
ساخت UI واقعی، خرید رسانه، هرگونه تعهد محتوا/برندینگ، شروع کدنویسی محصول (محیط F0-W09 برای ابزار داخلی مجاز است).
