# F3 — ساخت MVP هسته

- **بازه:** هفتهٔ ۶ تا ۱۶ · **پیش‌نیاز:** G1 (تحقیق) و G2 (دانش) — F2 در این فاز ادامه موازی دارد
- **گیت خروج:** G3 · **Trace:** T04 (امکانات) · T05 (قالب پاسخ) · T06 (UI/UX) · T08 (معماری) · T12 (MVP)

> **Flow مقصود (از T12، خلاصهٔ اجرایی S2):** «پرستار می‌آید ← عکس فیش را می‌گیرد ← سیستم خطا را نشان می‌دهد ← نامهٔ اعتراض را می‌دهد ← پرستار ارسال می‌کند» — **در کمتر از ۳ دقیقه**، بدون ثبت‌نام اجباری.

## ۱. دامنهٔ MVP (قفل‌شده در D1)

**در دامنه:** گفت‌وگوی تخصصی روی برش حقوق/دستمزد · ورودی صوتی · پرسش تکمیلی هوشمند · آپلود/دوربین فیش با تأیید انسانی OCR · محاسبه‌گر اضافه‌کاری/نوبت‌کاری/شب‌کاری · تولید پیش‌نویس نامهٔ قابل‌ویرایش + کپی · پاسخ سه‌سطحی (قطعی/احتمالی/نیازمند بررسی) · استناد قابل‌بازکردن · لندینگ + راهنما · PWA بدون نصب.
**خارج از دامنه (مرحلهٔ دوم، طبق T04):** پروندهٔ شخصی و یادآوری، جامعهٔ مشکلات مشابه، دستیار کمیسیون، پرداخت، اپ نیتیو، ارجاع پولی به کارشناس.

## ۳. گیت خروج G3

- [ ] Flow کامل «عکس فیش ← خطا ← نامه» در محیط Staging **< ۳ دقیقه** (میانگین ۱۰ اجرای کاربر واقعی).
- [ ] بدون ثبت‌نام قابل انجام باشد؛ ثبت‌نام فقط در گام ذخیره/پیگیری.
- [ ] خروجی خام OCR هیچ‌گاه وارد تحلیل نمی‌شود (تست کد + رفتار UI).
- [ ] دقت فیلدهای عددی پس از تأیید کاربر ≥ ۹۵٪؛ خطای محاسباتی موتور = صفر.
- [ ] هیچ پاسخِ تولیدشده در فهرست «ممنوع‌اللفظ v1» تخلف نداشته باشد (تست خودکار روی ۱۵۰ خروجی).
- [ ] ≥ ۷۰٪ پیش‌نویس‌های نامه بدون بازنویسی اساسی پذیرفته شوند.
- [ ] ۵۰ کاربر داخلی آزموده؛ ≥ ۶۰٪ توانسته‌اند «قدم بعدی» را بدون کمک توضیح دهند.
