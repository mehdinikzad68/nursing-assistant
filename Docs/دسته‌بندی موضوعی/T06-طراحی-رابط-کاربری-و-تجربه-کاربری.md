## محتوای استخراج‌شده

### ۱. فلسفه و سبک — [S4، S2]
- «طراحی UI در این حوزه، ۷۰٪ از موفقیت محصول است» چون مخاطب در حالت **خستگی شناختی** است.
- سبک پیشنهادی S4: **«Clinical Calm» (آرامش بالینی)** = ترکیب مینیمالیسم پزشکی + گیمیفیکیشن ملایم.
- سبک S2: **Calm Minimalism با رگه‌های Soft UI / Neumorphism**؛ «رابط نباید جیغ بزند… باید مثل یک پتوی نرم باشد».
- سه انگیزه: کاهش بار ذهنی (Cognitive Load)، **اعتماد بصری** («زشت = بی‌دقت»)، احساس مالکیت.

### ۲. پالت رنگ و تایپوگرافی
- **S4:** پس‌زمینهٔ سفید یخچالی/خاکستری خیلی روشن؛ رنگ اصلی آبی ملایم (Serenity Blue) یا سبز نعنایی (Teal)؛ هشدار: نارنجی ملایم یا قرمز آجری (نه قرمز جیغ).
- **S2:** ترکیب سرمه‌ای تیره (قانون/اعتماد) + سبز مریم‌گلی/تیل؛ **دارک‌مود اجباری** با پس‌زمینهٔ #121212 برای شیفت شب؛ اعداد حتماً **مونواسپیس**.
- **فونت:** Vazirmatn یا IranSans با وزن Medium/Bold؛ متن‌ها بزرگ و با فاصلهٔ خطوط زیاد؛ **هر پاراگراف حداکثر ۳ خط**، طولانی‌ها بولت‌وار شوند.

### ۳. ساختار صفحات و وایرفریم‌ها
**صفحهٔ اصلی — قانون ۳ ثانیه [S4]:** فقط یک نوار جستجوی بزرگ + دکمهٔ میکروفون؛ بدون منوهای پیچیده (درباره ما/تماس با ما در منوی همبرگری)؛ سه کارت سریع: «بررسی فیش حقوقی»، «نمونه نامهٔ اعتراض»، «حقوق و اضافه‌کاری».

**داشبورد اولیه به‌جای چت‌باکس خالی [S2]:** نیمهٔ بالا نوار جستجو/چت، نیمهٔ پایین «کارت‌های اقدام سریع»: «اعتراض به کسر کار»، «قوانین مرخصی استعلاجی»، «بررسی فیش حقوقی این ماه»؛ **باکس‌های آکاردئونی** برای متن قانون («مشاهدهٔ مستندات قانونی»)؛ **فلوچارت سه‌مرحله‌ای** برای پیگیری (تنظیم ← تحویل دبیرخانه ← پیگیری حراست)؛ بخش تأیید اسناد خوانده‌شده (تصویر در یک سمت، فرم‌های قابل‌ویرایش در سمت دیگر).

**ساختار چهار فضای رابط [S1]:**
| فضا | محتوا |
|---|---|
| صفحهٔ آغاز | کادر بزرگ «چه مشکلی پیش آمده؟»، افزودن سند، موضوعات پیشنهادی |
| گفت‌وگو | پرسش‌های تکمیلی کوتاه، اصلاح اطلاعات، نمایش پاسخ در بخش‌های خوانا |
| پرونده‌های من | مسائل ذخیره‌شده، اسناد، پیش‌نویس‌ها، وضعیت پیگیری (فقط با تمایل کاربر) |
| راهنما و منابع | حوزه‌های تحت پوشش، شیوهٔ استفاده، منابع استنادی |

**وایرفریم‌های تفصیلی [S4]:**
- **صفحهٔ بررسی فیش حقوقی (Payroll Scanner):** ورود ← آپلود با نوار پیشرفت و آیکون‌های مرتبط ← داشبورد نتایج (کارت وضعیت، لیست کارت‌های خطا با مبلغ/منبع/دکمهٔ اقدام، بخش «قدم بعدی»، کارت شرایط استخدامی) ← صفحهٔ جزئیات خطا با محاسبه‌گر و لینک منبع ← تایم‌لاین پیگیری.
- **لندینگ‌پیج (۷ بخش):** هیرو (تیتر + زیرعنوان + CTA اصلی + یادداشت «رایگان برای اولین بررسی») ← مشکلات/راه‌حل ← نحوهٔ کار در ۳ مرحله ← نمونهٔ نتیجه (Demo/Social Proof) ← اعتباربخشی ← FAQ ← فوتر با CTA نهایی.
- **داشبورد مرخصی:** سه کارت بالای صفحه (استحقاقی باقی‌مانده، سال قبل با مهلت، تداخل شیفت) + بخش «تحلیل هوشمند» با پیشنهاد متنی + تاریخچهٔ درخواست‌ها با دکمهٔ اعتراض.
- **پروفایل کاربری:** شناسنامهٔ شغلی (وضعیت استخدامی، محل خدمت، نوع قرارداد)، گاوصندوق اسناد با قفل، ترجیحات AI (سطح جزئیات، نوع اعلان)، تیک «بررسی شده توسط نظام پرستاری» و دکمهٔ «گزارش مشکل».
- **چهار صفحهٔ پایانی:** بررسی هوشمند سند / گفت‌وگوی تخصصی / مسیر اقدام / مشاورهٔ انسانی (جزئیات در T04).

### ۴. تعامل و بازخورد بصری — [S4]
- چت مثل واتساپ با حباب‌های نرم‌تر؛ به‌جای متن، **دکمه‌های آماده (Chips)**: «آیا شیفت شب داشتی؟» → [بله] [خیر].
- نوار پیشرفت ملایم هنگام آپلود؛ انیمیشن تیک سبز/ستاره هنگام اتمام کار (پاداش‌دهنده برای ذهن خسته).
- ۵ لایهٔ «پختگی طراحی»: Context-Aware (شیفت شب/Speed Mode)، Narrative-Driven (تایم‌لاین، اسلایدر قبل/بعد)، Personified AI (تغییر لحن)، Proactive (هشدارهای هوشمند)، Social-Proof (نشانگر «همکاران من»، بانک تجربیات).
- خلاصهٔ رنگ وضعیت‌ها: سبز=درست، زرد=نیاز به بررسی، قرمز/نارنجی=خطا.

### ۵. دسترس‌پذیری و اصول نهایی — [S1]
- متن فارسی راست‌به‌چپ، فونت خوانا، کنتراست مناسب، دکمه‌های قابل‌لمس، کارکرد درست با صفحه‌خوان و بزرگ‌نمایی (**WCAG 2.2**)؛ دکمه‌ها حداقل **۴۴px** (S4)؛ بدنهٔ متن حداقل **۱۶px** (S4).
- ثبت‌نام نباید جلوی «پرسیدن سؤال اولیه» را بگیرد.
- **اصل نهایی [S1]:** «پرستار خسته هم باید بتواند در کمتر از یک نگاه بفهمد سامانه چه می‌گوید و چه چیزی را هنوز نمی‌داند.»
