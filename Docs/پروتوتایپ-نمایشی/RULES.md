# RULES — قوانین پروژه برای مدیریت AI-Driven

> این سند **مبنای حقوقی تیم ایجنت‌ها** است: هر ایجنتی پیش از شروع کار باید این قواعد را در سیستم‌پرامپت خود داشته باشد. نقض هر قانون = توقف کار و بازگشت به LEAD.

---

## الف) قوانین حاکمیتی ( Governance — نقض‌ناپذیر)

| # | قانون | توضیح عملیاتی |
|---|---|---|
| **G1** | **تنها منبع حقیقت** | `PLAN.md` تعیین «چه چیزی»، `ROLES.md` تعیین «چه کسی»، `RULES.md` تعیین «چگونه». هیچ ایجنتی حق ندارد از سند چهارم به‌عنوان منبع استفاده کند. |
| **G2** | **تغییر دامنه فقط با PO** | افزودن/حذف صفحه یا سناریو = «درون‌ریزی Scope» → فقط PO می‌تواند تأیید کند و تغییر باید در `PLAN.md` ثبت شود. |
| **G3** | **بدون انتشار** | ممنوع: `deploy`، `publish`، خرید دامنه، اشتراک‌گذاری عمومی لینک، ثبت‌نام کاربر واقعی. فقط محیط محلی. |
| **G4** | **دادهٔ واقعی ممنوع** | ورودی سیستم فقط `data/mock` با `sample: true`. هیچ سند، نام، کد ملی یا فیش واقعی وارد پروژه نمی‌شود. |
| **G5** | **Trace اجباری** | هر کامپوننت/صفحه/متن باید به `T-xx` یا `DC-xx` ارجاع داشته باشد؛ بدون Trace → REVIEW رد می‌کند. |
| **G6** | **تست قبل از تحویل** | هیچ گزارش `done` بدون `npm run build` سبز پذیرفته نمی‌شود. |

## ب) چرخهٔ عمر یک تسک (State Machine)

```
draft ──► ready ──► in_progress ──► self_check ──► qa_review ──► content_review ──► done
  ▲                     │               │              │               │
  └────── blocked ◄──────┴───────────────┴──────────────┴───────────────┘
                     (هر فازِ ردشده: اصلاح توسط همان تسک‌دار، نه ایجنت دیگر)
```

| وضعیت | شرط ورود | شرط خروج |
|---|---|---|
| `draft` | کارت تسک کامل (Scenario + Scope + Acceptance) | تأیید LEAD |
| `in_progress` | فقط یک ایجنت همزمان روی یک Scope | فایل‌ها تغییر کرد + گزارش ساخت‌یافته |
| `self_check` | تسک‌دار خودش چک‌لیست زیر را می‌زند | همهٔ آیتم‌ها ✅ یا blocked ثبت‌شده |
| `qa_review` | QA فقط می‌خواند و می‌سنجد | `docs/QA.md` ✅ |
| `content_review` | فقط برای متن/ادعا — REVIEW | `docs/REVIEW.md` ✅ |
| `done` | هر دو بازبینی سبز | ثبت در `docs/STATUS.md` |
| `blocked` | هر ایجنتی در هر زمان | دلیل + پیشنهاد راه‌حل نوشته شود |

## ه) گردش کار روزانهٔ تیم AI (SOP)

```
صبح:
 ۱) PO: اولویت روز را در PLAN.md (بخش ۵) علامت می‌زند
 ۲) LEAD: تسک‌های روز را با کارت استاندارد توزیع می‌کند
 ۳) ساب‌ایجنت‌ها: موازی کار می‌کنند (UI-1 و UI-2 همزمان)
ظهر:
 ۴) هر ساب‌ایجنت: گزارش ساخت‌یافته → LEAD
 ۵) LEAD: build + تجمیع + ثبت STATUS
عصر:
 ۶) QA و REVIEW: بازبینی → گزارش
 ۷) PO: مرور گزارش روزانه + تصمیم «ادامه / اصلاح / توقف»
```

**پیام روزانهٔ LEAD به PO (قالب):**
```
📊 وضعیت روز [تاریخ]
• انجام‌شده: [Task-IDs] — [یک خط خروجی]
• در حال انجام: ...
• blocked: ... + علت
• ایرادات QA/REVIEW باز: ...
• تصمیم لازم از شما: ...
• فردا (پیشنهاد): ...
```

## ز) دستور شروع (برای اولین اجرای ایجنت)

```
۱. PLAN.md، ROLES.md، RULES.md را بخوان
۲. docs/STATUS.md را بساز با وضعیت: M0 در حال انجام
۳. نقش خود را از ROLES.md (جدول ۲) انتخاب و فقط در Scope آن عمل کن
۴. M0 را با کارت تسک زیر شروع کن:
   Task-ID: P-01 | From: PO → LEAD | Scenario: — | Scope: ساختار پوشه + قالب Next.js
   Acceptance: npm run dev بالا می‌آید + تم روشن/تیره + RTL
۵. هر پایان کار: گزارش ساخت‌یافته + build سبز
۶. انتشار ممنوع. داده فقط نمونه. Trace اجباری.
```
