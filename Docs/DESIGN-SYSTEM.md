## ۱. اصل حاکم بر رنگ

سیستم رنگ یک **سبز-آبی آرام و قابل‌اعتماد** است — نه آبی تند حقوقی و نه قرمز دائمی هشدار.

> **قاعدهٔ حیاتی:** سبز به‌معنای «نتیجه به نفع شما» **نیست**. این تمایز برای جلوگیری از اعتماد کاذب در محصول حقوقی ضروری است.

---

## ۲. قواعد استفاده

| قاعده | شرح |
|---|---|
| رنگ اصلی | فقط برای اقدام اصلی، لینک، فوکوس و بخش فعال |
| قرمز | فقط مهلت نزدیک، خطا یا هشدار واقعی — نه برند، نه دکمهٔ دائمی |
| سبز | «ثبت شد» یا «آماده بازبینی» — نه «حق با شماست» |
| کهربایی | «نیازمند تکمیل اطلاعات» |
| آبی | فقط منابع، استناد و اطلاعات تکمیلی |
| وضعیت | هرگز فقط با رنگ — همیشه متن یا آیکن همراه |
| فوکوس | حلقهٔ کیبورد همیشه واضح و پایدار |

## ۸. چگونه توکن اضافه کنیم

1. متغیر را در **هر دو بلوک** `:root` و `.dark` در `app/globals.css` تعریف کنید.
2. کلاس Tailwind را در `tailwind.config.ts` زیر `theme.extend.colors` اضافه کنید و به `var(--...)` وصل کنید.
3. **هرگز** هگز یا کلاس خام (`bg-teal-600`, `bg-slate-100`) در کامپوننت‌ها ننویسید — همیشه از توکن استفاده کنید، وگرنه تم تیره می‌شکند.

## ۹. توکن‌های داشبورد «حامی‌درمان» (نسخهٔ دوم رابط)

> افزوده‌شده در ۱۴۰۵/۰۷/۱۳ — داشبورد V2 بر پایهٔ طرح `code_artifact-react.tsx` پوشهٔ `Nursing Assistant-2/UI`.

### ۹٫۱ چرا توکن تازه لازم شد؟

طرح V2 ظاهر «سرمه‌ای عمیق + سبز-آبی» دارد که با پالت روشنِ بخش ۳ فرق می‌کند. به‌جای پخش‌کردن hex خام در ۱۵ کامپوننت، کل رنگ‌ها به توکن تبدیل شدند تا هم قاعدهٔ بند ۸ حفظ شود و هم حالت روشن/تیره بشکند.

### ۹٫۲ فهرست توکن‌ها

توکن‌ها به‌صورت **سه‌تایی RGB** ذخیره می‌شوند (`247 248 246`) تا Tailwind بتواند شفافیت بدهد: `bg-hami-card/70`.

| توکن | روشن | تیره | کاربرد |
|---|---|---|---|
| `--hami-canvas` | `#F7F8F6` | `#0B111E` | پس‌زمینهٔ صفحه (هم‌خانواده با `--app-bg`) |
| `--hami-card` | `#FFFFFF` | `#131C2E` | سطح کارت بنتو |
| `--hami-sub` | `#F1F4F2` | `#080D17` | فرم و ردیف درونی |
| `--hami-border` | `#D5DEE6` | `#FFFFFF` (با آلفا) | مرزها |
| `--hami-text` | `#18212B` | `#E7EEF4` | متن اصلی |
| `--hami-muted` | `#516070` | `#A8B6C4` | متن کمکی |
| `--hami-accent` | `#0F6E6B` | `#2DD4BF` | رنگ اصلی کنشی |
| `--hami-accent-strong` | `#0C5C59` | `#5EEAD4` | گرادیان دکمه |
| `--hami-on-accent` | `#FFFFFF` | `#04121A` | متن روی رنگ اصلی |
| `--hami-teal/amber/blue/purple/rose` | … | … | رنگ‌های دسته‌بندی کارت‌ها |

**نکتهٔ مهم:** توکن‌های روشنِ این جدول دقیقاً همان پالت تأییدشدهٔ بخش ۳ هستند (`#0F6E6B` و `#5EEAD4`)؛ فقط مقادیر تیره به سبز-آبی طرح V2 نزدیک شده‌اند. یعنی پالت مالک نقض نشده، تکمیل شده است.

### ۹٫۳ کلاس‌های ساختاری (به‌جای کلاس خام)

| کلاس | کاربرد |
|---|---|
| `.hami-glass` | سطح شیشه‌ای کارت بنتو (بلور ۱۶px + سایهٔ نرم) |
| `.hami-sub` | سطح درونی فرم/ردیف |
| `.hami-clay` / `.hami-clay-amber` / `.hami-clay-blue` | دکمهٔ سه‌بعدی (خودش `inline-flex` است) |
| `.hami-icon` | کاشی آیکن سه‌بعدی |
| `.hami-sensitive` | محو شدن محتوای حساس در «حالت محرمانهٔ استیشن» (کلاس فعال‌کننده: `.stealth-active` روی ریشهٔ داشبورد) |
| `.hami-fade-in` | ورود نرم (اعلان‌ها) |

مدار چرخانِ `Orbit3D` عمداً با کلاس‌های شرطی Tailwind (`animate-spin`) کنترل می‌شود، نه با کلاس CSS جدا — تا در حالت آرام اصلاً استایل انیمیشن تولید نشود.

### ۹٫۴ قواعد این داشبورد

1. **حالت آرام پیش‌فرض است.** انیمیشن مدار و کج‌شدن کارت‌ها فقط با کلید کاربر روشن می‌شود (پیش‌فرض `calmMotion = true`) تا خستگی بصری شیفت شب ایجاد نشود — همان اصل بخش ۷.
2. **کلاس پویا ممنوع.** `text-hami-${accent}` یا `bg-${tone}-500` در Tailwind تولید نمی‌شود؛ نگاشت رنگ‌ها باید ایستا باشد (`accentText`, `toneText`, `chipTone` در `components/hami/theme.ts`).
3. **هر عددِ نمایشی باید برچسب «نمونه» داشته باشد** یا اصلاً نمایش داده نشود؛ آمار ساختگی (مثل «بیش از ۸۰٪ موارد») در این داشبورد حذف شد.
4. هر قابلیتی که در این نسخه **واقعاً فعال نیست** (ورود گوگل، OCR، ارسال پیامک، جست‌وجوی منابع) باید در متن همان دکمه «غیرفعال در این نسخه» اعلام شود.
